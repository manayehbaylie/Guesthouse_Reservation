# Telegram bot setup

1. Create a bot with Telegram's BotFather. Put its token in `server/.env` as `TELEGRAM_BOT_TOKEN` and its username (without `@`) in `TELEGRAM_BOT_USERNAME`. The Contact page only needs the username to open the bot; the backend token is needed for polling and messages. Never put the token in the React app or commit it.
2. Apply the Prisma migration with `npx prisma migrate deploy` from `server`.
3. Restart the server after configuring the token. The server registers `/start`, `/help`, `/search`, `/reservations`, `/payments`, and `/unlink` with Telegram, then starts long polling. Without the token, the bot remains disabled.
4. Users can start with `/start`, then register a Guest account in chat using a Gmail address, email verification code, Ethiopian phone number, and password, or log in with an existing email and password. Password messages are deleted after receipt. A user can also connect an existing website account from Profile → Telegram chatbot → Connect Telegram and follow the generated link. Pairing codes are one-time, expire after 10 minutes, and are stored hashed in the database. `/unlink` or Profile → Disconnect disconnects the account.

Telegram account links are stored in `TelegramAccount` and in-chat conversation progress is stored in `TelegramConversation`; neither depends on a website refresh token or active session. `/search` guides Guest accounts through approved-guesthouse cities, areas, room type, required dates, available rooms, guest count, and reservation confirmation. Room availability and reservation creation use the platform's shared services. Confirmed reservations receive a hosted Chapa checkout link in chat; Chapa verification sends a payment confirmation to the linked Telegram account. `/reservations` and `/payments` show the linked account's existing records.

To enable the browser sign-in shown in Telegram's authorization flow, open the bot's Login Widget settings in BotFather, register every website origin as an allowed URL, and set the provided client ID as `TELEGRAM_LOGIN_CLIENT_ID` in `server/.env`. The website allows Telegram login only for an account already linked from Profile → Telegram. ID tokens are verified against Telegram's JWKS and a short-lived, one-time nonce. Restart the server after changing the environment. Do not place the Bot API token or Telegram client secret in the frontend.

Reservation and payment notifications saved by the existing application are also sent to linked Telegram accounts. All bot interactions are restricted to private chats.
